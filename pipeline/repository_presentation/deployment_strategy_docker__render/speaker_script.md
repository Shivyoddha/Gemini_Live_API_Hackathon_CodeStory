## Deployment Strategy (Docker & Render)

### Slide 1: Containerization with Docker
To ensure a consistent and reproducible environment, the IRIS Procurement Portal is containerized using Docker. The `Dockerfile` specifies the build instructions for the Ruby on Rails application image, including installing dependencies and copying application code. `docker-compose.yml` then orchestrates the application's services, defining the `web` service (our Rails app) and a `db` service for PostgreSQL. This setup allows developers to quickly spin up the entire application stack locally with simple commands. The `.dockerignore` file is crucial for optimizing build times by excluding unnecessary files and directories from being copied into the Docker image.

### Slide 2: Production Deployment with Render
For production deployment, the application is configured to run on the Render platform. The `render.yaml` file defines the necessary services and their configurations. It specifies a `web` service of type `ruby` and outlines the build and start commands. The build process includes installing gems and running database migrations (`bundle install && bundle exec rails db:migrate RAILS_ENV=production`), while the start command uses `bundle exec rails server -p ${PORT:-3000}` to launch the application. Key environment variables like `DATABASE_URL`, `GMAIL_USERNAME`, `GMAIL_PASSWORD`, and `SECRET_KEY_BASE` are expected to be configured within Render's dashboard, ensuring sensitive information is managed securely.

### Slide 3: Local Development and Production Environment
The contrast between local development and production deployment is clear. Locally, `docker-compose up` brings the development environment online, with database initialization handled through `docker-compose exec` commands. For production on Render, the `Procfile` specifies the exact command to start the server. Crucially, Render automatically injects the `DATABASE_URL` and other necessary environment variables, simplifying the deployment process. This separation ensures that development configurations (like local database paths or development email settings) do not interfere with the secure and robust production environment.
